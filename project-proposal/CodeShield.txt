% 1. HIGHER-ORDER GOAL
% ---------------------------------------------------------

\section{Higher-order Goal}

CodeShield aims to improve software security by automatically identifying potential vulnerabilities in source code before it is deployed. The engineering objective is to build a deployable platform that combines static code analysis with machine learning to detect, classify, and prioritize security vulnerabilities, giving developers a fast and reliable way to catch risky code early in the development cycle.


% ---------------------------------------------------------
% 2. PROBLEM STATEMENT
% ---------------------------------------------------------

\section{Problem Statement}

Modern software projects contain thousands of lines of code, which makes manual security inspection difficult, time-consuming, and error-prone. CodeShield is motivated by the following recurring challenges:

\begin{itemize}[leftmargin=0.6cm]

    \item \textbf{Large codebases:} Manually reviewing every line of a real-world project is impractical.

    \item \textbf{Hidden vulnerabilities:} Security issues may not produce visible errors during normal execution, so they go unnoticed until exploited.

    \item \textbf{Late detection:} Vulnerabilities discovered after deployment are significantly more expensive and disruptive to fix.

    \item \textbf{Different vulnerability types:} SQL injection, command injection, hardcoded credentials, and insecure input handling each require different detection strategies.

    \item \textbf{Prioritization:} Developers need to know which of the detected vulnerabilities are the most critical to fix first.

\end{itemize}

There is therefore a need for an automated system that can analyze source code and provide developers with the vulnerability type, its location, its severity, and actionable security guidance.


% ---------------------------------------------------------
% 3. PROPOSED SOLUTION
% ---------------------------------------------------------

\section{Proposed Solution}

We propose CodeShield, an ML-driven code vulnerability detection platform that accepts source code or a connected repository, analyzes it using a combination of static code analysis and machine-learning techniques, and generates a structured security report.

The main components are:

\begin{itemize}[leftmargin=0.6cm]

    \item \textbf{Code submission:} Upload individual source files or connect a Git repository.

    \item \textbf{Code preprocessing:} Parse and normalize source code into an analyzable form.

    \item \textbf{Static analysis:} Identify suspicious coding patterns and program structures using rule-based checks.

    \item \textbf{ML-based detection:} Classify potentially vulnerable code using trained models.

    \item \textbf{Risk assessment:} Assign a severity and confidence score to every detected vulnerability.

    \item \textbf{Security report:} Present the vulnerability type, its exact location, and a plain-language explanation.

    \item \textbf{Dashboard:} Let developers view scan history, trends, and outstanding issues over time.

\end{itemize}

\subsection{Worked Example}

Suppose the submitted code contains the following line:

\begin{verbatim}
query = "SELECT * FROM users WHERE id=" + user_id
\end{verbatim}

CodeShield would report this as:

\begin{itemize}[leftmargin=0.6cm]

    \item \textbf{Vulnerability:} SQL Injection -- High Severity

    \item \textbf{Location:} database.py, Line 12

    \item \textbf{Reason:} User-controlled input is directly concatenated into an SQL query without sanitization or parameterization.

\end{itemize}

% 5. SOLUTION APPROACH
% ---------------------------------------------------------

\section{Solution Approach}

\subsection{Code Preprocessing}

Submitted source code is first processed and converted into a representation suitable for analysis. Depending on the programming language, the system uses Abstract Syntax Trees (ASTs) or other code-parsing techniques to understand structures such as:

\begin{itemize}[leftmargin=0.6cm]

    \item Function calls

    \item Variable declarations and usage

    \item Control flow

    \item Imports and dependencies

    \item User inputs

    \item Database operations

\end{itemize}


\subsection{Static Analysis}

The system identifies known suspicious patterns using predefined security rules, forming a deterministic layer that does not rely entirely on machine learning.

For example, a rule may check whether user-controlled input is directly passed into a system command, which could indicate a potential command injection vulnerability.

\subsection{ML-Based Vulnerability Detection}

A machine-learning component analyzes code representations and classifies potentially vulnerable code into a defined set of supported vulnerability categories, rather than claiming to detect every possible vulnerability.

The initial supported categories are:

\begin{itemize}[leftmargin=0.6cm]

    \item SQL Injection

    \item Command Injection

    \item Hardcoded Credentials

    \item Insecure File Handling

    \item Cross-Site Scripting

    \item Weak Authentication

\end{itemize}

Framing the scope as ``selected vulnerability categories'' keeps the platform's claims realistic and measurable rather than promising exhaustive coverage.


\subsection{Risk Assessment}

Every detected issue is assigned:

\begin{itemize}[leftmargin=0.6cm]

    \item Vulnerability type

    \item Severity

    \item Confidence score

    \item Affected file and line number

    \item Explanation

\end{itemize}

The platform then prioritizes the most critical vulnerabilities so developers know what to fix first.

\section{Development and CI/CD Pipeline}

\begin{itemize}[leftmargin=0.6cm]

    \item \textbf{Continuous Integration (CI):} Automatically installs dependencies, runs unit tests, performs code-quality checks, and validates the application whenever new code is pushed to the project repository.

    \item \textbf{Continuous Delivery/Deployment (CD):} After successful checks, the application is built and prepared for deployment to the target environment.

    \item \textbf{Workflow:} Code Push $\rightarrow$ CI Checks $\rightarrow$ Tests $\rightarrow$ Build $\rightarrow$ CD $\rightarrow$ Deployment.

    \item The pipeline ensures that only tested and validated code is integrated and deployed.

\end{itemize}

\section{Evaluation Criteria}

CodeShield defines measurable evaluation criteria rather than relying on a general claim of accuracy.

\subsection{ML Evaluation}

\begin{itemize}[leftmargin=0.6cm]

    \item Precision

    \item Recall

    \item F1-score

    \item Accuracy

\end{itemize}

Precision and recall are treated as the most important metrics, since both false alarms and missed vulnerabilities carry real cost.

\subsection{System Evaluation}

\begin{itemize}[leftmargin=0.6cm]

    \item Average code scanning time

    \item Number of files successfully analyzed

    \item Detection coverage for supported vulnerability categories

    \item API response time

    \item Successful scan completion rate

\end{itemize}

% 12. RISKS AND MITIGATION

\section{Risks and Mitigation}

\begin{center}
\begin{tabular}{|p{0.38\textwidth}|p{0.52\textwidth}|}
\hline
\textbf{Risk} & \textbf{Mitigation} \\
\hline

False positives -- the system may flag safe code as vulnerable &
Combine ML predictions with static-analysis rules and report a confidence score rather than automatically declaring code unsafe.
\\
\hline

False negatives -- some vulnerabilities may be missed &
Clearly define supported vulnerability categories and evaluate performance using recall.
\\
\hline

Dataset limitations -- labelled vulnerable code can be hard to obtain &
Start with a limited set of vulnerability classes and use validated datasets and examples.
\\
\hline

Programming language differences -- security patterns vary by language &
Initially support one or two languages rather than claiming universal coverage.
\\
\hline

Security of uploaded code -- source code may contain confidential information &
Minimize storage, restrict access, and process uploaded code in isolated environments.
\\
\hline

\end{tabular}
\end{center}

\section{Summary}

CodeShield is a software-security platform that combines static code analysis and machine learning to automatically identify selected vulnerabilities in source code. The system analyzes submitted code, classifies potential security issues, estimates their severity, and presents developers with an actionable, prioritized security report through a web-based dashboard.

The project also incorporates a CI/CD pipeline to automate testing, validation, and deployment of the platform, helping the development team maintain a stable and reliable application.
